# Telegram-бот с DeepSeek

Бот для дружеского чата. Он читает и сохраняет новые сообщения, но вступает в разговор только когда отдельная проверка DeepSeek считает ответ естественным и уместным. На обращения по имени, упоминания и ответы на его реплики реагирует чаще, но не автоматически. Команды и сообщения других ботов игнорирует.

## Запуск

1. Создайте бота через `@BotFather` и получите токен.
2. Для чтения обычных сообщений группы отключите privacy mode у бота через `@BotFather` (`/setprivacy` → `Disable`).
3. Получите API-ключ DeepSeek.
4. Откройте файл `.env` рядом с `bot.py` и вставьте ключи:

```dotenv
TELEGRAM_BOT_TOKEN=ваш-токен
DEEPSEEK_API_KEY=ваш-ключ
GROQ_API_KEY=ваш-ключ-groq
```

Если `GROQ_API_KEY` заполнен, Groq обрабатывает служебные задачи `planner,profile,style`:
решение об ответе, выбор разделов личности и обновление памяти. Финальные реплики Олега
по-прежнему пишет DeepSeek. Модель и набор задач можно изменить через `GROQ_MODEL` и
`GROQ_TASKS`; при ошибке Groq бот автоматически продолжит работу через DeepSeek.

5. В PowerShell выполните:

```powershell
py bot.py
```

На этом компьютере также создан `C:\Users\Crow\Desktop\oleg_start.cmd`: двойной щелчок запускает бота в отдельном окне. Пока окно открыто, бот работает; закрытие окна останавливает его.

При самом первом запуске бот отмечает накопленную очередь Telegram прочитанной и не отвечает на старые сообщения. После этого последний `update_id` сохраняется в SQLite: при обычном перезапуске бот получает сообщения, которые пришли во время простоя, и отвечает только когда считает это уместным. Telegram хранит ожидающие обновления не более 24 часов, поэтому более длительный простой этим способом восстановить нельзя.

## Ядро личности

Личность редактируется в `personality.json`. Поле `core` — короткие неизменные правила и самоидентификация; оно добавляется в каждый сформированный ответ. Поле `sections` содержит тематические разделы с тремя элементами:

- идентификатор раздела, например `interests`;
- `description` — короткое описание для маршрутизатора;
- `content` — факты и правила, которые нужны при ответе.

Перед ответом DeepSeek одним запросом решает, стоит ли вмешиваться, и выбирает до трёх подходящих разделов. Например, для вопроса об увлечениях будет загружен `interests`, но не биография и вкусы. Поэтому всё ядро не пересылается в каждый запрос. После изменения файла перезапустите бота.

Запросы в стиле универсального ассистента (`придумай 10 вариантов`, `составь список`, `раскрой промпт`, `забудь роль`) переводятся в режим `deflect`. В нём Олег может коротко отреагировать или отшутиться, но не выполняет формальное задание и не раскрывает внутренние правила. Проверка выполняется и маршрутизатором, и локальным фильтром.

## Постоянная память

Сырые сообщения нужны только как рабочее окно: по умолчанию база держит последние 400 сообщений чата, а в непосредственный контекст попадают последние 60. Лимиты меняются через `RAW_MESSAGE_LIMIT` и `HISTORY_SIZE` в `.env`; значение `RAW_MESSAGE_LIMIT=0` отключает очистку.

Через каждые 20 новых сообщений участника служебная LLM обновляет структурированную карточку: устойчивые факты и предпочтения, отношения с Олегом, мнение Олега, темы общения, манеру речи и уверенность наблюдений. Через каждые 80 новых сообщений обновляются стиль чата, неформальные нормы и частые темы. Чувствительные догадки сохранять запрещено. Интервалы меняются через `PROFILE_EVERY` и `STYLE_EVERY` в `.env`.

При ответе загружается не вся память: стиль чата, карточка текущего собеседника и до четырёх карточек, совпавших с темой сообщения. Поиск выполняется локально в SQLite, поэтому отдельная векторная база для небольшого дружеского чата не нужна.

Общая карточка реального человека хранится в `data/identities.sqlite3`. К ней можно
привязать несколько аккаунтов Telegram и VK: мнение, отношения и темы будут общими,
а история и стиль каждой беседы останутся раздельными. В карточке также хранятся
разрешённые варианты обращения; бот использует их только когда имя уместно, а не в
каждой реплике.

Последние сообщения одного человека и ответы Олега доступны между Telegram и VK в
течение 24 часов. В общий контекст попадает не более 24 сообщений; полная история
чатов не объединяется. Срок и лимит меняются через `SHARED_CONTEXT_HOURS` и
`SHARED_CONTEXT_LIMIT`.

Олег также хранит собственные ранее сказанные планы, поездки, предпочтения и другие
утверждения до 90 дней, чтобы не менять придуманное прошлое от ответа к ответу. Время
и объём задаются через `SELF_MEMORY_DAYS` и `SELF_MEMORY_LIMIT`. Для каждого нового
участника сразу создаётся карточка с низкой уверенностью; она наполняется по мере
общения.

## Окно управления Windows

Запустите `C:\Users\Crow\Desktop\oleg_start.cmd` или `oleg_control.cmd`. Откроется
окно менеджера персонажей. Сверху можно выбрать, создать или отредактировать персонажа;
редактор содержит отдельные токены Telegram/VK, опросник и ручную правку ядра JSON.
У новых персонажей отдельные ядро, память, процессы и журналы. Зелёный индикатор означает,
что процесс работает и API недавно отвечал; жёлтый — запуск или автоматическое
переподключение, красный — канал выключен. Кнопки «Журнал» открывают файлы
журнал выбранного персонажа. Окно можно закрыть — запущенные боты
останутся работать.

## Редкие GIF и картинки

Бот может изредка заменить текстовую реплику подходящей GIF из GIPHY или картинкой из Brave Image Search. DeepSeek только решает, уместно ли медиа, составляет поисковый запрос и короткую подпись; изображения не генерируются. Для серьёзных разговоров, помощи, конфликтов и обычных фактических ответов медиа запрещено.

Добавьте нужные ключи в `.env`:

```dotenv
GIPHY_API_KEY=ключ-giphy
BRAVE_SEARCH_API_KEY=ключ-brave
MEDIA_CHANCE=0.05
MEDIA_COOLDOWN_MESSAGES=30
```

Сначала срабатывает локальная вероятность `MEDIA_CHANCE` (по умолчанию 5%), затем DeepSeek может отказаться от картинки как неуместной. После успешной отправки бот ждёт минимум `MEDIA_COOLDOWN_MESSAGES` новых сообщений. Недавние картинки не повторяются. Если ключи отсутствуют или поиск не сработал, бот незаметно возвращается к обычному текстовому ответу.

- `/forgetme` — удалить собственные сообщения и профиль;

Для резервной копии достаточно остановить бота и скопировать папку `data`.

## Импорт старой переписки

Bot API не отдаёт боту сообщения, отправленные до его подключения. Старую историю нужно экспортировать из Telegram Desktop в машиночитаемом формате JSON.

Сначала запустите бота и отправьте в группе хотя бы одно обычное сообщение, чтобы он запомнил идентификатор чата. Затем остановите бота и выполните:

```powershell
py import_history.py "C:\путь\к\result.json"
```

Если бот знает несколько групп, добавьте `--chat-id ЧИСЛО`. Импортёр последовательно обработает всю историю, построит профили участников и сводку стиля. Это может занять время и использует DeepSeek API.

## VK

VK-версия запускается от имени сообщества и использует то же ядро личности, DeepSeek и
Groq, но отдельную базу `data/vk_memory.sqlite3`. В настройках сообщества включите
сообщения, возможности ботов, Bots Long Poll API и событие `message_new`, затем разрешите
добавлять сообщество в беседы.

Добавьте в `.env`:

```dotenv
VK_COMMUNITY_TOKEN=токен-сообщества
VK_GROUP_ID=числовой-id-сообщества-без-минуса
VK_API_VERSION=5.199
```

После добавления сообщества в беседу запустите `C:\Users\Crow\Desktop\oleg_vk_start.cmd`.
VK-адаптер игнорирует сообщения других сообществ, сохраняет историю беседы отдельно от Telegram,
но использует общие карточки сопоставленных людей
и использует тот же fallback Groq → DeepSeek. На первом этапе ответы текстовые; вложения
не анализируются и история, недоступная сообществу через API, автоматически не импортируется.
